# 登录与访问 { #sign-in }

首次运行时选择他人如何登录。1.10.7 版本会要求确认一次该选择；账户、缓存和预填充设置会保留。之后可在 **用户 → 账户 → 访问与登录** 中更改。

## 五种模式

| 模式 | 用户需输入 | 应用的行为 |
|---|---|---|
| 用户名和密码 | 用户名和密码 | 本地账户。登录界面不要求 API 密钥 |
| API 密钥、用户名和密码 | 实例 API 密钥、用户名和密码 | 实例密钥加上本地账户 |
| API 密钥和单点登录 | 先输入实例 API 密钥，再使用已连接的服务 | 获准的单点登录账户和实例 API 密钥 |
| 单点登录 | 已连接的服务 | Google、GitHub、Microsoft、Apple 或其他 OpenID Connect 服务。登录界面不要求本地密码或 API 密钥 |
| 无需身份验证 | 无需输入 | 任何能够访问此应用的人都可使用管理功能。仅适用于所有人员和设备均受信任的网络 |

在保存模式之前，`Security__EnableAuthentication` 决定默认值。`true`（内置默认值）为 **API 密钥、用户名和密码**。`false` 为 **无需身份验证**。已保存的模式不会被该变量替换。

**用户名和密码** 与 **API 密钥、用户名和密码** 可以使用 HTTP。凭据和会话未经加密，因此在不可信的网络上请使用 HTTPS。设置界面不会在 HTTP 下选择单点登录模式。

!!! note "实例 API 密钥属于主管理员"
    所有模式都会保留实例 API 密钥，用于验证所有权和恢复。密钥归第一个账户（主管理员）所有。只有 **API 密钥、用户名和密码** 和 **API 密钥和单点登录** 会在登录时要求输入它。**重新生成 API 密钥** 会替换它，之前的密钥随即失效。

    ```bash
    docker exec lancache-manager cat /data/security/api_key.txt
    ```

## 单点登录

这里没有中心登录服务。在服务商处注册应用，然后填入凭据。Google、GitHub、Microsoft、Apple 和「其他（OpenID Connect）」可以同时连接。每种只保存一份；再次保存会更新该服务。

| 服务商 | 所需信息 |
|---|---|
| Google | 客户端 ID 和客户端密钥 |
| GitHub | 客户端 ID 和客户端密钥 |
| Microsoft | 应用程序（客户端）ID、客户端密钥和目录（租户）ID。使用租户 GUID，个人账户填 `consumers`。`common` 和 `organizations` 会被拒绝 |
| Apple | Services ID、Team ID、Key ID 和 `.p8` 密钥。应用会自行生成 Apple 的客户端密钥。必须使用 HTTPS 域名；localhost 和 IP 地址会被拒绝 |
| 其他（OpenID Connect） | HTTPS 签发者 URL、客户端 ID 和客户端密钥 |

设置页显示 **登录回调 URL** 和 **测试回调 URL**。把两个地址都复制到服务商的应用注册中。请用他人实际访问本应用的地址打开设置页，因为回调地址是根据该地址生成的。

**测试连接** 会执行一次真实登录。用于测试的账户会关联到主管理员，测试成功后这些设置才会生效。测试失败不会更改当前的登录设置。

其他用户按主体标识符授权，而不是电子邮件地址或显示名称。GitHub 使用数字账户 ID。Microsoft 使用 `租户 GUID:对象 GUID`。

### 回调地址

单点登录需要 HTTPS。设置界面即使在 localhost 上也要求 HTTPS。只在局域网或 VPN 内解析的域名即可，无需公网托管。除 Apple 以外的服务商，仅当主机是 localhost 或回环地址时，服务器才接受 HTTP 地址，而设置界面仍然要求 HTTPS。Apple 要求 HTTPS 域名，并拒绝 localhost 和任何 IP 地址。

## 切换模式

现有账户会话仍然有效。可在 **用户 → 会话** 中结束它们。切换到需要登录的模式后，共享的无身份验证访问会被撤销。由单点登录创建的管理员还没有密码。切换到 **用户名和密码** 或 **API 密钥、用户名和密码** 之前，需要先设置密码。

如果单点登录导致无法进入，请在宿主机上运行：

```bash
./data/scripts/reset-main-admin-password.sh
```

该脚本发送实例 API 密钥和主机恢复令牌，然后打开一小时的窗口。应用会要求输入 API 密钥、主管理员用户名和新密码。详见[密码恢复](password-recovery.md)。
