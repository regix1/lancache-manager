# 访问与登录 { #sign-in }

首次运行时需要选择用户如何登录。升级的实例会请你确认一次该选择；账户、缓存和预填充设置都会保留。之后可在 **用户 → 账户 → 访问与登录** 中更改。

## 五种模式

| 模式 | 用户需输入 | 适用场景 |
|---|---|---|
| 用户名和密码 | 用户名和密码 | 大多数部署 |
| API 密钥、用户名和密码 | 先 API 密钥，后用户名和密码 | 在登录页增加一道检查 |
| API 密钥和单点登录 | 先 API 密钥，后单点登录账户 | 同上，配合外部服务商 |
| 单点登录 | 单点登录账户 | Google、GitHub、Microsoft、Apple 或 OpenID Connect |
| 免认证访问 | 无需输入 | 仅限受信任的局域网 |

- **免认证访问** 会让任何能访问该应用的人使用其管理功能。
- 两种单点登录模式都需要 HTTPS。
- 密码和 API 密钥模式可以使用 HTTP。在不受信任的网络中请使用 HTTPS，以免密码和会话 Cookie 以明文传输。

### 选择之前的默认值

在保存模式之前，由 `Security__EnableAuthentication` 这个 compose 变量决定默认值：

| 取值 | 默认模式 |
|---|---|
| `true`（内置默认） | API 密钥、用户名和密码 |
| `false` | 免认证访问 |

保存模式后，该变量不再改变它。

!!! note "API 密钥始终有效"
    密钥属于第一个账户，即主管理员。在任何模式下它都可用于所有权确认和账户恢复。只有两种 API 密钥模式会在登录时要求输入它。

    ```bash
    docker exec lancache-manager cat /data/security/api_key.txt
    ```

    **重新生成 API 密钥** 会替换该密钥，旧密钥立即失效。

## 单点登录

这里没有中心登录服务。你需要在每个服务商处注册一个应用，并把它的信息填入本应用。可以同时连接多个服务商。

| 服务商 | 所需信息 |
|---|---|
| Google | 客户端 ID 和客户端密钥 |
| GitHub | 客户端 ID 和客户端密钥 |
| Microsoft | 应用程序（客户端）ID、客户端密钥和目录（租户）ID |
| Apple | Services ID、Team ID、Key ID 和 `.p8` 私钥 |
| 其他（OpenID Connect） | HTTPS 颁发者 URL、客户端 ID 和客户端密钥 |

- **Microsoft：** 填写租户 GUID，个人账户填 `consumers`。`common` 和 `organizations` 会被拒绝。
- **Apple：** 本应用会自动生成 Apple 的客户端密钥。Apple 要求 HTTPS 域名，不接受 localhost 和 IP 地址。

### 设置步骤

1. 使用用户实际访问本应用的地址打开它。回调 URL 基于该地址生成。
2. 把 **登录回调 URL** 和 **测试回调 URL** 复制到服务商的应用注册中。你无需自己打开它们。
3. 点击 **测试连接**，它会执行一次真实登录。
    - 通过后，用于登录的账户会关联到主管理员，设置随即生效。
    - 失败则不改变任何内容，因此一次失败的尝试不会破坏已经可用的配置。

### 允许其他用户登录

通过服务商提供的账户 ID 授权其他用户，而不是电子邮件地址或显示名称。

| 服务商 | ID 格式 |
|---|---|
| GitHub | 数字账户 ID |
| Microsoft | `租户 GUID:对象 GUID` |

### 回调地址

- 单点登录需要 HTTPS，即使在 localhost 上也是如此。
- 域名无需公开。只在局域网或 VPN 内可解析的名称就足够。

## 切换模式

- 现有会话保持登录。可在 **用户 → 会话** 中结束它们。
- 选择任何登录模式都会立即停止共享的免认证访问。
- 通过单点登录创建的账户还没有密码。切换到密码模式前请先设置密码。

### 因单点登录无法登录

在宿主机上运行恢复脚本：

```bash
./data/scripts/reset-main-admin-password.sh
```

它会打开一个一小时的恢复窗口。在浏览器中输入 **用户名**、**密码**、**确认密码** 和 **API 密钥**。之后你会以主管理员身份登录，并可修复登录方式。完整步骤见[密码恢复](password-recovery.md)。
